## 这是什么

**队友视野（TeamVision）** 是一款面向 FPS 玩家的实时画面共享工具：共享端把自己的游戏画面采集、编码后通过网络发送给队友，队友端用一个置顶、鼠标穿透的悬浮窗实时观看，做到「边打边看队友视角」。

- 低延迟：DXGI 硬件采集 + NVENC 硬件编码，默认 30 FPS、码率自适应。
- 跨网络：同一局域网直连，或通过樱花内网穿透（SakuraFrp）跨公网连接。
- 多人观看：一个共享端可同时广播给多个观看端，慢客户端各自丢帧、互不拖累。
- 不打扰操作：悬浮窗默认置顶 + 鼠标穿透，配合全局热键随时切换频道与画面源。

## 架构

```
┌──────────────┐    TCP 直连（同一局域网）     ┌──────────────┐
│   共享端      │◄──────────────────────────────│   观看端      │
│ fps-host.exe │  host 默认监听 127.0.0.1:5700 │ fps-viewer   │
└──────┬───────┘  （局域网直连需改 0.0.0.0）    └──────────────┘
       │ frpc 隧道（跨公网）
       ▼
┌──────────────────────────────┐
│   樱花内网穿透节点 (SakuraFrp) │
│   远端端口 ──映射──► 本地 5700 │
└──────────────────────────────┘
       ▲
┌──────┴───────┐
│   观看端      │   server_addr = 节点IP/域名:远端端口
│ fps-viewer   │
└──────────────┘
```

- **共享端（fps-host.exe）**：采集屏幕 → H.264/H.265(HEVC) 编码（NVENC 硬件优先，软件 x264 / JPEG 自动回退）→ TCP 广播给所有观看端，默认监听 `127.0.0.1:5700`（仅本机与 frp 隧道可连；回环地址会**同时监听 IPv4 `127.0.0.1` 与 IPv6 `[::1]`**，因此樱花 frpc 以 `localhost` 回连也能连通）。
- **观看端（fps-viewer.exe）**：连接 `server_addr`，按流内 codec 标记自动选择 H.264/HEVC 解码，悬浮显示画面；默认需要注册/登录（账户准入）。

## 功能特性

| 分类 | 说明 |
|---|---|
| 视频编码 | HEVC / H.264，NVENC 硬件编码优先；不可用时自动回退软件 x264，再回退 JPEG |
| 屏幕采集 | DXGI 硬件采集（低延迟、可解决独占全屏黑屏），不可用时自动回退 mss(GDI) |
| 带宽自适应 (ABR) | 网络差时自动下调质量 / 缩放 / 码率，码率上下限可配 |
| 多人观看 | 每客户端独立发送线程 + 最新帧队列，慢客户端只丢自己的帧 |
| 悬浮窗 | 置顶、鼠标穿透、不透明度可调、显示宽度可调，不挡游戏操作 |
| 多画面源 (MultiView) | 观看组内多人互看，热键循环切换画面源 |
| 全局热键 | 见下方「快捷键」 |
| 内网穿透 | 内置 frpc 管理，一键启动樱花隧道；自动识别已安装的 SakuraFrp |
| 回环双栈监听 | 默认的 `127.0.0.1` 会**同时**监听 IPv4 `127.0.0.1` 与 IPv6 `[::1]`，樱花 frpc 把隧道本地地址写成 `localhost`（Windows 优先解析 `::1`）也能连上；两个 socket 都只绑回环，安全性不变 |
| 隧道可用性自检 | 配好 `frp.public_addr` 后，共享端启动时会从公网地址回连一次并完成握手：成功记「公网隧道自检通过」，失败直接写明是"没指向监听端口"还是"只监听了一个地址族" |
| 登录体验 | 登录框直接显示服务端拒绝原因（如 `账号不存在`、注册已关闭）并预填上次用户名；输错凭据后约 1 秒自动重弹，不会"消失"（详见下方 FAQ） |
| 日志诊断 | `logs\app_*.log` 滚动日志；GUI 内实时性能区与客户端列表 |

>
> 自行构建时（`build_exe.bat` → `build_installer.bat`）产物在 `dist\`：`fps-host\`、`fps-viewer\`、
> `frpc.exe`（构建前若把 frpc.exe 放在仓库根，脚本会自动复制进 `dist\`）、`TeamVision-Setup-1.3.0.exe`。

### 方式二：绿色版

> 如需跨公网使用，还要把 `frpc.exe` 放到两个目录的**上一级**（共享端同处）；
> 若该位置已有随包提供的 `frpc.exe`，则无需自行下载。

## 快速开始

### 路径一：局域网直连（建议先验证）

> ⚠️ 共享端**默认只监听 `127.0.0.1`**（仅本机与 frp 隧道可连），局域网直连需要先把监听地址
> 改成 `0.0.0.0`：打开共享端控制台 →「传输参数」→ 监听地址填 `0.0.0.0` →「应用传输设置」→
> **重启共享端**（监听 socket 只在启动时绑定一次）。

1. 共享端双击 `fps-host\fps-host.exe`，按上面的说明把监听地址改为 `0.0.0.0` 并重启，等待出现「服务已启动，监听 0.0.0.0:5700」。
2. 确认共享端内网 IP：`ipconfig` 查看 IPv4 地址（如 `192.168.1.100`）。
3. 观看端双击 `fps-viewer\fps-viewer.exe`，在频道管理中把地址改为 `192.168.1.100:5700` 并连接。
4. 首次连接需要在弹框中注册/登录（默认开启账户准入）；约 1~2 秒后看到悬浮画面。

> **本机自测（最省事的验证方式）**：共享端保持运行，观看端加一个 `127.0.0.1:5700` 频道即可
> 本机走完整链路（握手 → 登录 → 收流），不依赖局域网或隧道。登录框会在这里弹出——它只代表
> "本机共享端要求账户"，与网络无关。

### 路径二：公网穿透（樱花 SakuraFrp）

1. 在 [樱花控制台](https://console.natfrp.com) 注册、创建 **TCP** 隧道（本地端口填 `5700`），记下隧道 ID 与访问令牌 token。
2. `frpc.exe` 放到两个程序目录的上一级（安装包已放在安装根）——从控制台下载的 Windows amd64 版即可。
3. 共享端 GUI 的「frpc 区」填写 `token`、`tunnel_ids` 与 `public_addr`，点「启动」（或勾选自动启动）。
4. 观看端把 `server_addr` 设为 `节点IP或域名:远端端口` 并连接。

> 映射关系：`公网节点IP:远端端口 ──► 共享端本地 127.0.0.1:5700`。一个 TCP 隧道即可承载多个观看端。
> **隧道的本地地址写 `localhost` 或 `127.0.0.1` 都可以**：共享端监听回环时会同时覆盖 `[::1]` 与
> `127.0.0.1`。填写了 `public_addr` 时，共享端启动后会自己做一次公网回连自检并打印结论。
>
> 公网隧道把服务暴露到了互联网，请务必保留「账户准入」开启，并把「账户注册」设为
> `仅首个账户可注册` 或 `关闭`，否则任何拿到地址的人都能自建账号看你的屏幕。

完整部署、frpc 配置与排障详见 [`docs/部署操作文档.md`](docs/部署操作文档.md)。

### 安全默认与升级迁移

- **默认只监听本机**：开箱即用的形态下不存在对外监听的端口，局域网内的其他人无法连上；
  需要局域网直连时在控制台的「传输参数」里把监听地址改成 `0.0.0.0`。
  回环形态下共享端会同时绑定 `127.0.0.1` 与 `[::1]`（都只绑回环），因此内网穿透能正常工作，
  而端口对局域网依旧不可达。
- **默认开启账户准入**：观看端首次连接需要注册/登录，共享端能看到「谁在看」。
  默认注册策略是 `open`（保持旧的零配置体验）；把 `auth.allow_register` 改成 `bootstrap`
  或 `closed` 可以关掉自助注册——公网隧道场景建议这样做。
- **认证窗口有下界**：`auth.auth_timeout` 会被夹到 `[240, 3600]`，避免把窗口设得比观看端
  等待还短而重新引入"输对了也登录失败"。
- **一次性的配置迁移**：从 1.3.0 及更早升级时，如果配置里显式写着 `listen_host: 0.0.0.0`
  且 `auth.enabled: false`，首次启动会自动升级为上面的安全默认值，并在日志里逐条列出改动
  （`配置已升级到 v2（更安全的默认值）：…`）；迁移时若 `auth_timeout` 偏小会一并抬高。
  想恢复旧行为，按提示在控制台改回去即可。
- 启动时会检查暴露面：监听 `0.0.0.0` 且准入关闭、或准入开启但允许自助注册，都会写一条
  WARNING 到日志（`%LOCALAPPDATA%\TeamVision\logs\`，共享端控制台的「运行日志」区实时可见），
  不会静默放过。

## 从源码构建

需要 Python 3.10 环境与 [conda](https://docs.conda.io/)（项目脚本默认使用名为 `fps-screen` 的环境）。

```bash
# 1. 安装依赖（首次）
setup.bat

# 2. 生成图标与启动画面（assets/app.ico、assets/splash.png）
python gen_assets.py

# 3. 打包 exe（PyInstaller onedir，输出到 dist\fps-host\ 与 dist\fps-viewer\）
build_exe.bat

# 4. 生成安装包（需先安装 Inno Setup 6）
build_installer.bat

# 5. 运行测试（480 项单元测试，约 2 分钟）
run_tests.bat
```

在仓库根目录直接运行 `python host.py` / `python viewer.py` 也能工作。注意两点：

- **采集后端 `dxgi` 的 vendor 依赖**：`dxcam` 与 `comtypes` 以 vendored 形式放在 `vendor\`
  （取自 GitHub `ra1nty/DXcam`，**非** PyPI 上过时的 0.0.5），`vendor\` 不入库，需按
  [`docs/部署操作文档.md`](docs/部署操作文档.md) §7.3/§7.4 手工装入。程序在延迟导入 `dxcam`
  前会**自动把 `vendor\` 接入 `sys.path`**，所以源码运行时"独占全屏黑屏 → 把 `capture.backend`
  设为 `dxgi`"这条排障建议同样有效（若日志出现 `dxgi 后端不可用，回退 mss`，先确认 `vendor\dxcam` 存在）。
- **打包产物**：`dist\fps-host\`、`dist\fps-viewer\`（各自含 `_internal\`）、`dist\frpc.exe`
  （构建前把 `frpc.exe` 放在仓库根，脚本会自动复制）、`dist\TeamVision-Setup-1.3.0.exe`。
  `build_exe.bat` 末尾会调用 `sign_exe.ps1` 做 Authenticode 签名：脚本**签名后会复核文件本身**，
  若时间戳签名导致哈希不符会自动去掉时间戳重签（大安装包上实测会触发）。**签名前请先退出
  正在运行的 fps-host / fps-viewer**，否则 exe 被占用会签名失败。

主要依赖（见 `requirements.txt`）：`mss`、`opencv-python`、`numpy`、`pillow`、`pywin32`、`av`。

## 近期修复（v1.3.0 构建后）

以下问题已在当前构建中修好，逐条证据与验证方式见
[`docs/修复记录-2026-09-11-BUG审查报告.md`](docs/修复记录-2026-09-11-BUG审查报告.md)：

| 现象（修复前） | 修复 |
|---|---|
| 走公网隧道时画面完全传不过来，两端日志都"正常" | 默认 `127.0.0.1` 只绑了 IPv4 回环，而 frpc 以 `localhost` 回连会走 `::1`。现改为**回环双栈**（同时绑 `127.0.0.1` 与 `[::1]`），并新增启动后的**公网回连自检** |
| 准入开启后"明明输对密码却登不进去" | 认证窗口下界提到 **240 秒**（观看端最坏要等 ≈180 秒），迁移旧配置时一并抬高 |
| 共享端开了登录，观看端**看不到登录框**；输错一次后登录框长时间不出现 | 登录框现在直接显示服务端拒绝原因 + 预填上次用户名，输错后**约 1 秒**自动重弹；"弹框/冷却"都会写日志（旧版本会静默压住 30 秒以上） |
| 单个共享成员的上行限速形同放宽一倍 | 令牌桶补充速率改为名义值（实测 600 Kbps 档曾跑出 1312 Kbps） |
| 采集后端启动即失败时共享端永久无画面并刷日志 | 失败走重建自愈路径，同类告警 10 秒去重 |
| 源码运行时 `dxgi` 后端静默降级成 mss（独占全屏黑屏排障建议失效） | 延迟导入 `dxcam` 前自动把 `vendor\` 接入 `sys.path` |
| 大安装包签名后验签失败（`HashMismatch`），打包脚本却报成功 | 签名后复核文件本身，失败自动去掉时间戳重签；报告失败即返回非 0 |

## 常见问题

| 现象 | 处理 |
|---|---|
| 局域网里连不上共享端 | 默认只监听 `127.0.0.1`：控制台「传输参数」把监听地址改成 `0.0.0.0` 并**重启共享端** |
| 观看端一直「连接中/无画面」 | 先用局域网直连验证：观看端填 `共享端IP:5700`，`ping` 确认可达 |
| 局域网能连、公网连不上 | ①确认共享端日志出现 `frpc 已启动`，核对隧道为 TCP、本地端口=5700；②**最常见的原因是隧道本地地址写成了 `localhost`**：Windows 优先解析为 `::1`，若共享端只监听 IPv4 回环就连不上（本版本已默认同时监听 `[::1]`；若日志出现「已配置 frp 隧道，但本机只监听了 …（未覆盖 IPv6 回环）」则按提示处理：把樱花隧道的本地地址显式改成 `127.0.0.1`，或把监听地址设为 `0.0.0.0` 后重启）。判别方法：看樱花 frpc 日志是否出现 `连接映射目标 [tcp://localhost:5700] 失败`；共享端启动后也会自动做一次公网回连自检，成功记「公网隧道自检通过」，失败会写明原因 |
| **共享端开了登录，观看端却看不到登录框** | 登录框**只在 TCP 握手成功之后**才会弹，按顺序查两处：①**共享端是否在运行**——进程没起来（或窗口被关掉）时 frpc 日志会刷 `连接映射目标 [tcp://localhost:5700] 失败, 连接被拒绝`，观看端停在 `连接提前关闭，收到的数据不完整`，此时**永远不会**弹登录框；②观看端日志里搜 `登录框`：`需要账户（服务端要求登录），已弹出登录框` = 确实弹了（本版本起会留这条日志），`登录框处于冷却中（N 秒后可再次弹出）` = 上一次是手动点了取消。旧版本在输错凭据后会静默压住登录框 30 秒以上（叠加退避），本版本已改为**约 1 秒后带原因重弹** |
| 连上但要求登录 / 输错一次后登录框"消失" | 默认开启账户准入；输错凭据时登录框会红字显示服务端原因（`账号不存在`/`用户名或密码错误`）并预填上次用户名，约 1 秒后自动重弹，直接改对再点「登录」即可。「账户注册」为 `仅首个账户`/`关闭` 时注册会被拒绝，原因同样显示在框内 |
| 忘记共享端口令 / 想换账号 | 共享端控制台「传输参数」→「账户注册」改为 `开放`（或 `仅首个账户`），然后在观看端登录框点「注册并登录」新建账号；也可清掉 `%LOCALAPPDATA%\TeamVision\accounts.json` 后用同样方式重建（会清空所有已有账号） |
| 连上但黑屏 | 独占全屏采集黑屏：把 `capture.backend` 设为 `dxgi`，或改为窗口化/无边框全屏（源码运行也有效，见「从源码构建」） |
| 画面卡顿、延迟高 | 降 `fps`/`scale`/`bitrate_kbps`，开启 `perf.adaptive`，或用 `capture.region` 限定区域 |
| 双击 exe 无反应 | 查看 `%LOCALAPPDATA%\TeamVision\logs\` 当日日志；确认 `_internal` 目录与 exe 同级未被删改 |
| 提示「未找到 frpc 程序」 | 把 `frpc.exe` 放到 `fps-host\`、`fps-viewer\` 的上一级目录（安装包会自带一份） |

更多排障见 [`docs/部署操作文档.md`](docs/部署操作文档.md)。
