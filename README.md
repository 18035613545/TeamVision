## 这是什么

**队友视野（TeamVision）** 是一款面向 FPS 玩家的实时画面共享工具：共享端把自己的游戏画面采集、编码后通过网络发送给队友，队友端用一个置顶、鼠标穿透的悬浮窗实时观看，做到「边打边看队友视角」。

- 低延迟：DXGI 硬件采集 + NVENC 硬件编码，默认 30 FPS、码率自适应。
- 跨网络：同一局域网直连，或通过樱花内网穿透（SakuraFrp）跨公网连接。
- 多人观看：一个共享端可同时广播给多个观看端，慢客户端各自丢帧、互不拖累。
- 不打扰操作：悬浮窗默认置顶 + 鼠标穿透，配合全局热键随时切换频道与画面源。

## 架构

```
┌──────────────┐    TCP 直连（同一局域网）     ┌──────────────┐
│   共享端      │◄──────────────────────────────│   观看端      │
│ fps-host.exe │  host 默认监听 127.0.0.1:5700 │ fps-viewer   │
└──────┬───────┘  （局域网直连需改 0.0.0.0）    └──────────────┘
       │ frpc 隧道（跨公网）
       ▼
┌──────────────────────────────┐
│   樱花内网穿透节点 (SakuraFrp) │
│   远端端口 ──映射──► 本地 5700 │
└──────────────────────────────┘
       ▲
┌──────┴───────┐
│   观看端      │   server_addr = 节点IP/域名:远端端口
│ fps-viewer   │
└──────────────┘
```

- **共享端（fps-host.exe）**：采集屏幕 → H.264/H.265(HEVC) 编码（NVENC 硬件优先，软件 x264 / JPEG 自动回退）→ TCP 广播给所有观看端，默认监听 `127.0.0.1:5700`（仅本机与 frp 隧道可连）。
- **观看端（fps-viewer.exe）**：连接 `server_addr`，按流内 codec 标记自动选择 H.264/HEVC 解码，悬浮显示画面；默认需要注册/登录（账户准入）。

## 功能特性

| 分类 | 说明 |
|---|---|
| 视频编码 | HEVC / H.264，NVENC 硬件编码优先；不可用时自动回退软件 x264，再回退 JPEG |
| 屏幕采集 | DXGI 硬件采集（低延迟、可解决独占全屏黑屏），不可用时自动回退 mss(GDI) |
| 带宽自适应 (ABR) | 网络差时自动下调质量 / 缩放 / 码率，码率上下限可配 |
| 多人观看 | 每客户端独立发送线程 + 最新帧队列，慢客户端只丢自己的帧 |
| 悬浮窗 | 置顶、鼠标穿透、不透明度可调、显示宽度可调，不挡游戏操作 |
| 多画面源 (MultiView) | 观看组内多人互看，热键循环切换画面源 |
| 全局热键 | 见下方「快捷键」 |
| 内网穿透 | 内置 frpc 管理，一键启动樱花隧道；自动识别已安装的 SakuraFrp |
| 日志诊断 | `logs\app_*.log` 滚动日志；GUI 内实时性能区与客户端列表 |

### 快捷键（观看端）

| 热键 | 功能 |
|---|---|
| `Ctrl + Alt + X` | 切换鼠标穿透 |

## 下载与安装

### 方式一：安装包（推荐）

[下载 TeamVision-Setup-1.3.0.exe（186 MB）](https://github.com/18035613545/TeamVision/releases/tag/v1.3.0) —— 安装后自动放置共享端与观看端两个程序目录。

> 程序为 **onedir** 形态，各自带 `_internal` 运行库目录：
> `%LOCALAPPDATA%\Programs\TeamVision\fps-host\fps-host.exe`（共享端）与

> `config.json`、`accounts.json` 与 `logs\` 统一写在 `%LOCALAPPDATA%\TeamVision\`（安装目录不可写时

### 方式二：绿色版

把 `dist\fps-host\` 与 `dist\fps-viewer\` 两个目录（以及可选的 `frpc.exe`）放到同一处即可运行；
`config.json` 首次运行自动生成到 `%LOCALAPPDATA%\TeamVision\`。

> 如需跨公网使用，还要自行从樱花内网穿透下载 `frpc.exe` 放到两个目录的**上一级**（共享端同处）。

## 快速开始

### 路径一：局域网直连（建议先验证）

> ⚠️ 共享端**默认只监听 `127.0.0.1`**（仅本机与 frp 隧道可连），局域网直连需要先把监听地址
> 改成 `0.0.0.0`：打开共享端控制台 →「传输参数」→ 监听地址填 `0.0.0.0` →「应用传输设置」→
> **重启共享端**（监听 socket 只在启动时绑定一次）。

1. 共享端双击 `fps-host\fps-host.exe`，按上面的说明把监听地址改为 `0.0.0.0` 并重启，等待出现「服务已启动，监听 0.0.0.0:5700」。
2. 确认共享端内网 IP：`ipconfig` 查看 IPv4 地址（如 `192.168.1.100`）。
3. 观看端双击 `fps-viewer\fps-viewer.exe`，在频道管理中把地址改为 `192.168.1.100:5700` 并连接。
4. 首次连接需要在弹框中注册/登录（默认开启账户准入）；约 1~2 秒后看到悬浮画面。

### 路径二：公网穿透（樱花 SakuraFrp）

1. 在 [樱花控制台](https://console.natfrp.com) 注册、创建 **TCP** 隧道（本地端口填 `5700`），记下隧道 ID 与访问令牌 token。
2. 从控制台下载 Windows amd64 版 `frpc.exe`，放到两个程序目录的上一级（安装包已放在安装根）。
3. 共享端 GUI 的「frpc 区」填写 `token` 与 `tunnel_ids`，点「启动」（或勾选自动启动）。
4. 观看端把 `server_addr` 设为 `节点IP或域名:远端端口` 并连接。

> 映射关系：`公网节点IP:远端端口 ──► 共享端本地 127.0.0.1:5700`。一个 TCP 隧道即可承载多个观看端。
> 公网隧道把服务暴露到了互联网，请务必保留「账户准入」开启，并把「账户注册」设为
> `仅首个账户可注册` 或 `关闭`，否则任何拿到地址的人都能自建账号看你的屏幕。

完整部署、frpc 配置与排障详见 [`docs/部署操作文档.md`](docs/部署操作文档.md)。

## 配置参考（config.json）

配置文件统一放在 `%LOCALAPPDATA%\TeamVision\`（源码运行时放在项目目录），缺失时自动生成，
旧配置升级时自动补全新字段（不覆盖已有值）。`accounts.json` 与 `logs\` 同此规则。

### 共享端 `host`

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen_host` | `127.0.0.1` | 监听地址。默认**只允许本机与 frp 隧道**接入；局域网直连需改为 `0.0.0.0`（改完要重启共享端） |
| `port` | `5700` | 服务端口，需与 frp 隧道本地端口一致 |
| `fps` | `30` | 目标帧率 |
| `jpeg_quality` | `80` | JPEG 质量 1~100（回退编码时使用） |
| `scale` | `1.0` | 画面缩放系数（0.5=半分辨率，省带宽） |
| `capture.monitor` | `1` | 采集显示器编号（从 1 开始） |
| `capture.region` | `null` | 自定义采集区域；null=全屏 |
| `capture.backend` | `dxgi` | 采集后端：`dxgi`（硬件）/ `mss`（GDI，兼容性最好） |
| `perf.adaptive` | `true` | 带宽自适应开关 |
| `perf.quality_min` | `40` | 自适应最低质量 |
| `perf.scale_min` | `0.25` | 自适应最低缩放 |
| `codec.encoder` | `auto` | 编码选择：`auto`/`hevc`/`nvenc`/`x264`/`jpeg` |
| `codec.bitrate_kbps` | `2500` | 编码码率（Kbps） |
| `codec.keyint` | `60` | 关键帧间隔（帧） |
| `codec.min_bitrate_kbps` | `400` | ABR 码率下限 |
| `codec.max_bitrate_kbps` | `6000` | ABR 码率上限 |
| `codec.preset` | `""` | 编码器预设，空=默认低延迟预设 |
| `auth.enabled` | `true` | 账户准入：观看端必须注册/登录后才能取流 |
| `auth.allow_register` | `open` | 自助注册策略：`open` 任何客户端可注册；`bootstrap` 仅首个账户可注册；`closed` 完全关闭（由共享端控制台添加） |
| `auth.auth_timeout` | `150` | 认证阶段总时限（秒） |
| `frp.*` | — | 内网穿透配置，见部署文档 |

### 安全默认与升级迁移

- **默认只监听本机**：开箱即用的形态下不存在对外监听的端口，局域网内的其他人无法连上；
  需要局域网直连时在控制台的「传输参数」里把监听地址改成 `0.0.0.0`。
- **默认开启账户准入**：观看端首次连接需要注册/登录，共享端能看到「谁在看」。
  默认注册策略是 `open`（保持旧的零配置体验）；把 `auth.allow_register` 改成 `bootstrap`
  或 `closed` 可以关掉自助注册——公网隧道场景建议这样做。
- **一次性的配置迁移**：从 1.3.0 及更早升级时，如果配置里显式写着 `listen_host: 0.0.0.0`
  且 `auth.enabled: false`，首次启动会自动升级为上面的安全默认值，并在日志里逐条列出改动
  （`配置已升级到 v2（更安全的默认值）：…`）。想恢复旧行为，按提示在控制台改回去即可。
- 启动时会检查暴露面：监听 `0.0.0.0` 且准入关闭、或准入开启但允许自助注册，都会写一条
  WARNING 到日志（`%LOCALAPPDATA%\TeamVision\logs\`，共享端控制台的「运行日志」区实时可见），
  不会静默放过。

### 观看端 `viewer`

| 字段 | 默认 | 说明 |
|---|---|---|
| `server_addr` | `127.0.0.1:5700` | 默认连接地址（无频道时使用） |
| `display_width` | `480` | 悬浮窗显示宽度（像素），高度按原比例 |
| `alpha` | `0.9` | 窗口不透明度 0~1 |
| `click_through` | `true` | 鼠标穿透 |
| `panel_topmost` | `true` | 悬浮窗置顶 |
| `channels` | `[]` | 频道列表 `[{"name":"默认频道","addr":"IP:端口"}]` |

> 配置项以代码 `common.py` 的 `DEFAULT_CONFIG` 为单一真源；若文档与代码不符，以代码为准。

## 从源码构建

需要 Python 3.10 环境与 [conda](https://docs.conda.io/)（项目脚本默认使用名为 `fps-screen` 的环境）。

```bash
# 1. 安装依赖（首次）
setup.bat

# 2. 生成图标与启动画面（assets/app.ico、assets/splash.png）
python gen_assets.py

# 3. 打包 exe（PyInstaller onedir，输出到 dist\fps-host\ 与 dist\fps-viewer\）
build_exe.bat

# 4. 生成安装包（需先安装 Inno Setup 6）
build_installer.bat

# 5. 运行测试（357 项单元测试，约 111 秒）
run_tests.bat
```

主要依赖（见 `requirements.txt`）：`mss`、`opencv-python`、`numpy`、`pillow`、`pywin32`、`av`。
采集后端 `dxcam` 及其依赖 `comtypes` 以 vendored 方式提供（取自 GitHub `ra1nty/DXcam`，**非** PyPI 上过时的 0.0.5）。

## 常见问题

| 现象 | 处理 |
|---|---|
| 局域网里连不上共享端 | 默认只监听 `127.0.0.1`：控制台「传输参数」把监听地址改成 `0.0.0.0` 并**重启共享端** |
| 观看端一直「连接中/无画面」 | 先用局域网直连验证：观看端填 `共享端IP:5700`，`ping` 确认可达 |
| 局域网能连、公网连不上 | 确认共享端日志出现 `frpc 已启动`，核对隧道为 TCP、本地端口=5700 |
| 连上但要求登录/无法注册 | 默认开启账户准入；「账户注册」为 `仅首个账户`/`关闭` 时需共享端放行，注册失败原因会显示在观看端面板 |
| 连上但黑屏 | 独占全屏采集黑屏：把 `capture.backend` 设为 `dxgi`，或改为窗口化/无边框全屏 |
| 画面卡顿、延迟高 | 降 `fps`/`scale`/`bitrate_kbps`，开启 `perf.adaptive`，或用 `capture.region` 限定区域 |
| 双击 exe 无反应 | 查看 `%LOCALAPPDATA%\TeamVision\logs\` 当日日志；确认 `_internal` 目录与 exe 同级未被删改 |
| 提示「未找到 frpc 程序」 | 把自行下载的 `frpc.exe` 放到 `fps-host\`、`fps-viewer\` 的上一级目录 |

更多排障见 [`docs/部署操作文档.md`](docs/部署操作文档.md)。
