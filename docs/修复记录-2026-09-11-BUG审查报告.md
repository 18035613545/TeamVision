## 1. 高严重程度

### A0 回环双栈监听（公网共享完全不可用的根因）

- `host.py::_is_loopback_alias()` / `_LOOPBACK_ALIASES`：把 `127.0.0.1`、`localhost`、`::1`
  识别为"具体回环地址"。
- `host.py::bind_listener()`：回环地址时创建**两个**监听 socket（`127.0.0.1` + `[::1]`，均只绑回环，
  不降低安全性），`runtime._server` 仍指向 IPv4 主 socket 保持既有语义，
  `runtime._servers` 保存全部；`runtime.listen_dual_loopback` 供日志/自检使用。
  返回值由单 socket 改为**socket 列表**，`run_server`/`shutdown` 同步改为全部关闭。
- `host.py::_accept_loop()`：`_as_server_list()` 归一化入参；单 socket 仍走原路径
  （`_accept_loop_single`，保持单测注入假 server 的语义），多 socket 走 `select` 轮询的
  `_accept_loop_multi`；失效 socket 只从集合剔除，不拖垮另一地址族。
- `host.py::_log_security_notice()`：默认形态不再把"设计上可达"当"已经可达"；
  IPv6 回环绑定失败且配了 frp 时明确告警（A0 建议 2 的兜底自检）。
- `host.py::_start_tunnel_selfcheck()`（同时满足 C14）：共享端启动后异步
  `connect(public_addr)` → 发 `FS02` → 等 `OK02`，失败时写出可操作的结论
  （隧道本地地址/端口未指向共享端、或只监听单一地址族）。
- `common._upgrade_config()`：迁移到回环地址时补一条说明；不再声称隧道必然失效。
- 文档同步：`README.md`（部署方式一/FAQ）、`docs/部署操作文档.md`（§5 端口链路、FAQ）。

**为什么没走"迁移时保留 0.0.0.0"**：正解（回环双栈）让默认值 `127.0.0.1` 与隧道天然兼容，
保留迁移可维持第 131 条的安全默认（也保住 `tests/test_item131_hardening.py` 的既有断言）。

### A1 令牌桶补充速率

`host.py::ClientInfo.allow_upstream()` 拆成 `rate_bytes_s = max_kbps × 125` 与
`burst_bytes = rate_bytes_s × 2`：补充用前者、削顶用后者。原来把"2 秒额度"当成每秒补充量，
长期吞吐是名义值的 2 倍。

### A2 采集后端启动即失败时永久无法自愈

`pipeline.CaptureSource.set_params()`：`cap is None` 时不再 `self.cap.set_params(...)`（那会抛
`AttributeError` 并被吞成每 0.5 秒一条 WARNING，且让 `host._capture_loop` 永远到不了 `grab()`
的自愈分支），改为走 `_rebuild()` 并返回重建结果；新增 `_warn_throttled()` 把同类告警降到 10 秒一条。

### A3 凭据等待

`viewer.Channel._ask_credentials()`：

- 队列满时对淘汰项 `done.set()` 且写入 `{"error": ...}`，等待者立刻返回（不再空等 120 秒）；
- 等待改成 `done.wait(0.5)` 轮询 + `_stop_evt`/`_running` 检查，`Channel.stop()` 新增
  `_wake_pending_credentials()` 就地置位本频道未完成请求；
- C19 的"等界面就绪"60 秒轮询同样改为 `_stop_evt.wait(0.1)`。

## 4. 用户在真机装包后报障的追加修复（第 133 条）

**报障**：host 端开了账户准入，viewer 端"连登录页面都没有"。

**实测定位（读两端日志 + 现场复现 + 截图）**：登录框本身一直是好的（截图里「账户认证」框正常弹出），
用户感知不到它由**两个独立原因**叠加造成：

1. `Channel._authenticate` 在服务端拒绝凭据（`账号不存在`/`用户名或密码错误`）后设置
   `_prompt_blocked_until = now + 30`，下一次重连 `_ask_credentials` 直接返回 None 并被当成
   "用户取消"，**叠加**重连指数退避（可涨到 30 秒）——输错一次后登录框长时间不再出现，
   用户只会以为"根本没有登录入口"。日志里也没有任何"弹过框/被冷却压住"的记录。
2. 共享端进程没运行时（frpc 日志刷 `连接映射目标 [tcp://localhost:5700] 失败, 连接被拒绝`），
   viewer 停在握手之前，**任何**登录框都不会出现——这时用户看到的也是"没有登录页面"。

**修复（第 133 条，仅 viewer.py）**：

| 位置 | 改动 |
|---|---|
| `Channel._authenticate` | 凭据被拒时**不再**设置 30 秒弹框冷却；改为记录 `_auth_error_text`（服务端原因）与 `_last_auth_user`，并把 `_retry_delay` 复位为 0（约 1 秒后重连重弹） |
| `Channel._ask_credentials` | 被冷却压住时写日志「登录框处于冷却中（N 秒后可再次弹出）」；正常入队时写「需要账户（服务端要求登录），已弹出登录框；上次尝试：X」 |
| `ViewerApp._credentials_dialog` | 新增 `error_text` / `default_user` 两个参数：服务端原因以红字直接显示在框内，用户名预填上次尝试值；预填时焦点落在密码框、用户名全选 |
| `ViewerApp._process_cred_requests` | 把 `_auth_error_text` / `_last_auth_user` 传给对话框（测试替身非字符串时容错），读后即清避免陈旧报错 |

| 产物 | 说明 |
|---|---|

**第 132 条（本轮发现）**：`sign_exe.ps1` 只看 `Set-AuthenticodeSignature` 的返回值就判成功，
而实测在 140MB 的安装包上带时间戳签名会落到 `HashMismatch`（签名块已写入、文件哈希与签名
不符），脚本却以退出码 0 报告成功——用户拿到的是验签失败的安装包。已改为**签名后复核文件
本身**，复核不通过则去掉时间戳重签，仍不通过则如实报失败（返回 `$false`，脚本退出码 1）。
`build_exe.bat`/`build_installer.bat` 对该退出码的既有处理是"记警告不中断"，因此打包流程行为不变。

> 注意：`sign_exe.ps1` 与仓库中一致为 **UTF-8 带 BOM**。本机 `pwsh` 实为 Windows PowerShell
> **5.1**，无 BOM 时会把中文按 ANSI 解码并触发解析错误；改动该脚本时务必保留 BOM。

## 7. 真机排障速查：viewer 端"看不到登录页面"

按下面顺序看**证据**，两步即可定位（本次报障即由此确认）：

1. **viewer 日志**（`%LOCALAPPDATA%\TeamVision\logs\app_*.log`）里搜 `登录框`：
   - `需要账户（服务端要求登录），已弹出登录框` → 登录框确实弹了（第 133 条起会留这条日志）；
   - `登录框处于冷却中（N 秒后可再次弹出）` → 上一步是**手动取消**，N 秒后会自动再弹；
   - 连 `正在连接` 都没有或一直 `连接提前关闭，收到的数据不完整` → 根本没连上共享端，
     **此时不会有任何登录框**（登录发生在 TCP 握手之后）——去第 2 步。
2. **共享端是否在跑 + 隧道是否打得到本机**：
   - 共享端 GUI 顶部应显示 `监听 127.0.0.1:5700 · 已启动 · 准入开启`；进程没了就点「启动」/重开程序；
   - 樱花 frpc 日志（`C:\ProgramData\SakuraFrpService\logs\`）若刷
     `连接映射目标 [tcp://localhost:5700] 失败, 连接被拒绝`，就是共享端没监听该端口；
   - 共享端在跑时可用一条命令自检：本地 `127.0.0.1:5700` 与 `[::1]:5700` 都应回 `OK02`。
3. 登录凭据：共享端「账户注册」为 `关闭`/`仅首个账户` 时，viewer 只能**登录**已有账户，
   `注册并登录` 会被拒（登录框里会红字写出原因）。忘记口令可在共享端控制台把注册策略改为
   `开放`，或清掉 `%LOCALAPPDATA%\TeamVision\accounts.json` 后用 `注册并登录` 重建账号。
