### 一句话总评

> 代码的"深度"很好（并发、协议、编码器细节都考虑到了），但"广度"不够：**缺 CI、缺类型、缺模块边界**，导致 2018 行的 `host.py` 和 2790 行的 `viewer.py` 里，同一类错误（配置校验、锁归属、帧拷贝、Tk 对象生命周期）以不同形式反复出现。优化的主线不是"再修 100 个 bug"，而是**把反复出错的模式收敛成共享组件**。

### 2.1 P0 —— 可用性硬伤（建议 1 天内修）

#### A1｜`accept_loop` 遇任意 `OSError` 永久退出，服务静默失去接受能力 **✅ 已修复**

```python
# host.py:1330-1335
def accept_loop():
    while not runtime.stop_event.is_set():
        try:
            sock, addr = server.accept()
        except OSError:
            break          # ← 注释假设"server socket 已关闭"，但 OSError 不止这一种
```

`accept()` 会抛出**可恢复**的瞬时错误：`WSAEMFILE`（fd 耗尽）、`WSAENOBUFS`、`WSAENETDOWN`，以及部分平台的 `ECONNABORTED`。任一发生即 `break`，而 `runtime._server` 仍非 None（`host.py:1324`）、`server_up` 仍为 True（`host.py:831`）：

- GUI 显示"服务运行中"，日志**零输出**；
- 已连接的观众继续收帧（发送线程独立）；
- **新观众永远连不上**。

这正是最难排查的一类故障：看起来"只是对方网络不好"。

**修法**
```python
def accept_loop():
    while not runtime.stop_event.is_set():
        try:
            sock, addr = server.accept()
        except OSError as e:
            if runtime.stop_event.is_set():
                break                      # 真正的关闭
            log.warning("accept 失败（%.1fs 后重试）: %s", 0.05, e)
            time.sleep(0.05)
            continue
        threading.Thread(target=handle_client,
                         args=(sock, addr, runtime), daemon=True).start()
```
**验收**：新增单测——让 `server.accept` 连续抛 3 次 `OSError` 后返回一个真连接，断言 `handle_client` 被调用 1 次；再置 `stop_event` 断言循环退出。

```ini

DefaultDirName={autopf}\TeamVision        ; = C:\Program Files\TeamVision
```

`logger.py:146-169` 已经实现了 `_writable_log_dir()`（exe_dir/logs → `%LOCALAPPDATA%\TeamVision\logs` → 临时目录），但**同一思路没有用在配置与账户上**。后果：

| 场景 | 结果 |
|---|---|
| 首次以非管理员双击（配置尚不存在） | `load_config()` 抛 `PermissionError`；`host.py:1961` 在 `_install_excepthooks()`(1963) **之前**调用 → windowed 打包无 stderr → **静默退出，无日志**（正是 README FAQ「双击 exe 无反应」） |

| 注册账户 | `host.py:164` 同样写 exe_dir → 注册失败 |

**修法（两步，任选其一或都做）**
1. **首选**：安装目录改为用户级 `DefaultDirName={localappdata}\Programs\TeamVision`（无需提权，读写皆可）。
2. **兜底**：在 `common.py` 抽出 `data_dir()`，与 `logger._writable_log_dir()` 同逻辑，用于 `config.json`、`accounts.json`（日志目录复用同一个）；首次运行发现 exe 目录不可写时把已有配置**迁移**到用户目录，并保持"exe 目录可写则仍用绿色版行为"。

**验收**：在 `C:\Program Files\` 下手动放一份只读目录的 exe，双击应能启动、能改设置、日志与配置都落到 `%LOCALAPPDATA%\TeamVision`。

#### A3｜观看端面板预览：Tk 图像悬空 → 每次切源后预览永久失效 **[实证]** **✅ 已修复**

日志（当前发布版，2026-09-08 18:36）：
```
[WARNING] 面板预览刷新失败，跳过本次（定时器续排，不停更）
  File "viewer.py", line 1784, in _panel_refresh_preview
  File "tkinter\__init__.py", line 1675, in configure
_tkinter.TclError: image "pyimage227" doesn't exist
```

对应源码：
```python
# viewer.py:1780-1785
if clear:
    self._panel_last_serial = -1
    self._panel_last_idx = -1
    # 先让 label 脱离旧图像再释放引用（同上，避免删除仍在显示的图像）
    self._preview_label.configure(image=None, text="暂无画面")   # ← 第 1784 行
    self._panel_photo = None
```

注释写的意图是对的，**但写法无效**：`tkinter` 的 `_options()` 会**丢弃值为 `None` 的选项**，所以 `configure(image=None, ...)` 实际只发了 `-text`，label 的 `-image` 仍指向旧图；紧接着 `self._panel_photo = None` 让 `PhotoImage.__del__` 执行 `image delete pyimageN`，label 从此持有一个**已被删除的图像名**。之后任何 `configure`（哪怕只改文字）都会让 Tk 重新布局并解析该图像 → `TclError`。

实证输出（附录 B.1）：
```
2) tkinter _options(image=None) -> ('-text', 'no frame')      ← image 选项被丢弃
3) after configure(image=None): label -image = 'pyimage1'     ← 图像仍在
5.1) TclError: image "pyimage1" doesn't exist                 ← 释放引用后必现
6) image='' -> label -image = ''                              ← 正确写法
7) correct clear path: configure OK
```

**修法**
```python
# 用空字符串显式清空（不要用 None）
self._preview_label.configure(image="", text="暂无画面")
self._panel_photo = None
```
或更省事：构造期放一张 1×1 透明占位 `PhotoImage` 常驻，永不置 None。
另建议把该 `except` 的日志**去重**（同一条异常 1 小时内只记一次），避免 66 条刷屏掩盖真问题。

**验收**：新增单测用真 Tk（`tk.Tk()` + `withdraw()`）模拟"贴图 → 清空 → 再贴图"，断言无 `TclError`；或直接断言 `label.cget("image") == ""`。

### 2.2 P1 —— 稳定性与协议正确性

| # | 问题 | 位置 | 后果 | 建议改法 |
|---|---|---|---|---|

```python
import gc, tkinter as tk
from PIL import Image, ImageTk
root = tk.Tk(); root.withdraw(); label = tk.Label(root)
photo = ImageTk.PhotoImage(Image.new("RGB", (8, 8), (10, 20, 30)))
label.configure(image=photo, text="")
print("2) _options:", label._options({"image": None, "text": "no frame"}))
label.configure(image=None, text="no frame")          # viewer.py:1784 的写法
print("3) -image =", repr(label.cget("image")))
del photo; gc.collect()                               # viewer.py:1785 的写法
try:
    label.configure(text="x")                         # 之后任何 configure
except tk.TclError as e:
    print("5) TclError:", e)
label2 = tk.Label(root); p2 = ImageTk.PhotoImage(Image.new("RGB", (8, 8)))
label2.configure(image=p2); label2.configure(image="")  # 正确写法
print("6) -image =", repr(label2.cget("image")))
root.destroy()
```

```
2) tkinter _options(image=None) -> ('-text', 'no frame')     ← image 选项被丢弃
3) after configure(image=None): label -image = 'pyimage1'    ← 图像未被清空
5) TclError: image "pyimage1" doesn't exist                  ← 释放引用后任何 configure 必炸
6) image='' -> label -image = ''                             ← 正确写法
```
