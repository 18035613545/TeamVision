## 1. 结论摘要

| 问题 | 判断 |
|---|---|
| 会被内核级反作弊（Vanguard / BattlEye / EAC）判定为外挂？ | **否**。缺少作弊链的全部关键环节（读游戏内存、注入、驱动、输入注入） |
| 会被杀软 / 反作弊的启发式**误报**（拦启动、提示可疑）？ | **已显著降低**。主因（onefile 自解压、tasklist 子进程）已修复；剩余主因是自签证书，需 CA 证书才能解决 |
| 会被游戏判定违规、账号处罚？ | **这是真正的风险，且与技术检测无关**。实时画面共享在竞技 FPS 里属于"提供额外信息优势"，多数用户协议禁止；被封多来自人工复核/举报，不是"误报"。README 已补使用边界声明 |

一句话：**技术上没有外挂特征，且已不是"隐身"配置；"检测不到"不等于"合规"。**

## 3. 会被启发式盯上的点（真正的误报来源）

### 3.1 PyInstaller onefile 自解压（最高优先级）—— ✅ 已修复
- `fps-host.spec:12-40` 为 onefile，`console=False`；运行时会释放到 `%TEMP%\_MEIxxxxxx` 并**从临时目录执行子进程**。
- 这是 AV/EDR 的经典启发式链（"写入临时目录 → 执行"），也是本项目 README 自己承认的问题（`README.md:204`）。
- 产物体积 ~100 MB / 侧，含完整 Python 运行时，熵值高。
- **影响**：杀软拦截、SmartScreen 拦截、部分反作弊的"未知可执行体"上报。**不构成封号依据**。
- **修复**：两个 spec 均改为 onedir（`COLLECT`），构建/安装脚本同步更新；已实跑打包 + 冒烟启动验证。

### 3.2 自签名证书 ≈ 等于未签名 —— ⚠️ 部分修复
- `sign_exe.ps1:61-77` 无商业证书时自动创建 `CN=TeamVision` 自签证书；`certs\TeamVision-CodeSigning.pfx` 密码硬编码为 `TeamVision`。
- 自签证书在**其他机器上仍显示"未知发布者/Unknown"**，无法进入任何反作弊/AV 白名单。
- `certs/` 已在 `.gitignore:25` 忽略（这点做对了）。
- **修复**：脚本新增 `-Release` 模式，对外发布时**拒绝**回退到自签并明确报错；输出末尾会区分"本机自签"与"CA 签发"。
  **购买 CA 证书这一步只能由作者本人完成**，代码层面无法替代。

### 3.3 行为画像与"外部雷达/截图挂"重合 —— ✅ 已部分收敛
组合特征：**DXGI 采集 + 置顶穿透悬浮窗 + 全局热键 + 对外 TCP 监听 + `tasklist` 子进程**。

- 悬浮窗样式：`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`（`viewer.py:2880-2893`）。
  - `TOOLWINDOW` 使其**不进 Alt+Tab、不上任务栏**；配合置顶/穿透，属于"刻意不引人注意的窗口"。
  - `viewer.py:2894-2896` 注释写明：把窗口标题改成 `TeamVision` 是**为了避免 "FPS" 关键词被扫描**。这一条本身无害，但"有意规避关键词检测"的代码注释，在人工审查场景下观感不佳。
- 结论：缺少"输入注入"这一环，行为链不完整，不会触发外挂判定；但某些行为型监控会把它标记为"待观察"，从而带来**非封号类**的兼容性摩擦（启动失败、被提示关闭）。
- **修复**：删除了刻意中性化标题的代码与注释（标题交由正常窗口标题）；`tasklist` 改为 `CreateToolhelp32Snapshot`；
  对外监听默认关闭（见 4.1）。`TOOLWINDOW` 保留——它是"不抢游戏焦点"的正当需求（Discord/OBS 同款）。

### 3.4 `tasklist` 子进程 —— ✅ 已修复
- `host.py:553` 用 `tasklist /FI "IMAGENAME eq SakuraFrpService.exe"` 探测樱花服务。
- 等价于 MITRE T1057（进程发现），且会拉起 `cmd.exe` 子进程。风险很低，但在 EDR 日志里是一条可被关注的记录。
- **修复**：改用 `CreateToolhelp32Snapshot` + `Process32FirstW/NextW`（不拉起子进程、不打开目标进程句柄），
  并有单测锁定"不再 shell out"。

### 3.5 NVENC / FFmpeg 模块加载
- `fps-host.spec:6` 用 `collect_all('av')` 把 FFmpeg DLL 打进 exe，运行时加载 `nvEncodeAPI64.dll`。
- 这些是常见的正常模块名，本身不被针对；仅说明"加载硬件编码器"不是可疑行为（OBS 同样如此）。

## 4. 与反作弊无关、但风险更高的两点

### 4.1 画面外传的授权边界（安全/隐私）
- `config.json` 默认 `listen_host = 0.0.0.0`、`auth.enabled = false`（`host.py:1232-1234` 准入关闭时直接放行）。
- 即：同一局域网内**任何人**无需凭据即可观看共享端屏幕；若叠加 frpc 公网隧道，边界更大。
- 这不会触发反作弊，但会被安全审计视为"未授权对外传输屏幕内容"，也是"木马/RAT"启发式的高危组合（屏幕采集 + 对外监听 + 无鉴权）。**建议默认开启准入。**

### 4.2 合规风险 > 技术风险
- TeamVision 的功能是"让队友实时看到我的游戏画面"。在竞技类 FPS（CS2 / VALORANT / PUBG / 三角洲行动等）中，这属于**向队伍提供额外信息优势的第三方工具**，普遍被用户协议禁止。
- 此类处罚通常来自人工复核、对局举报或赛事规则，而不是反作弊自动检测。**因为检测不到就认为安全，是误判。**

## 5. 修复建议（按性价比排序）

1. **对外发布用 CA 代码签名证书（OV/EV）**：替换 `sign_exe.ps1` 的自签回退；EV 证书对 SmartScreen 与部分白名单有效。
2. **onefile → onedir 打包**：`fps-host.spec` / `fps-viewer.spec` 的 `EXE(...)` 去掉 onefile 形态（改为 onedir + Installer 分发）。这是降低"自解压执行"误报最直接的一步，代价仅是产物变成目录。
3. **默认关闭对外监听 + 默认开启准入**：`common.py` 的 `DEFAULT_CONFIG` 中 `host.listen_host` 改 `127.0.0.1`，`auth.enabled` 改 `true`；公网场景一律走 frp 隧道。
4. **去掉 `tasklist` 子进程**：`host.py:553` 改用 `psutil` 或 `win32process`/`EnumProcesses` 直接枚举，避免拉起 `cmd.exe`。
5. **窗口标题不要"刻意中性化"**：`viewer.py:2894-2896` 建议保留正常标题 `TeamVision`，并删除解释性注释（规避关键词的意图不必写进代码）。
6. **保持现状，不要新增以下能力**：输入注入、`SetWindowDisplayAffinity`/`WDA_EXCLUDEFROMCAPTURE`（防截屏）、`SetWindowsHookEx` 低级钩子、驱动、进程内存访问。目前一条都没有，这是本项目最大的"清白资产"。
7. **README 增加使用边界说明**：明确"竞技类 FPS 使用可能违反游戏用户协议"，把风险交给使用者判断，同时降低作者被牵连的概率。
