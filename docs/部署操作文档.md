# 队友视野（SakuraVision）部署操作文档

> 适用于 v1.0.0。本文档覆盖：环境与产物说明、两种部署路径（局域网直连 / 公网 frp 穿透）、
> 樱花 frp（frpc）配置、端口映射关系、`config.json` 全字段参考、常见问题排查。

---

## 1. 系统架构与部署路径

```
┌──────────────┐   TCP 直连（同一局域网）   ┌──────────────┐
│   共享端      │◄───────────────────────────│   观看端      │
│ fps-host.exe │   host 监听 0.0.0.0:5700   │ fps-viewer   │
└──────┬───────┘                            └──────────────┘
       │ frpc 隧道（跨公网）
       ▼
┌──────────────────────────────┐
│   樱花 frp 节点（natfrp）      │
│   远端端口 ──映射──► 本地 5700 │
└──────────────────────────────┘
       ▲
┌──────┴───────┐
│   观看端      │   server_addr = 节点IP/域名:远端端口
│ fps-viewer   │
└──────────────┘
```

- **共享端（fps-host.exe）**：采集屏幕 → H.264/H.265(HEVC) 视频编码（NVENC 硬件优先，软件/JPEG 自动回退）→ TCP 广播给所有已连接观看端。默认监听 `0.0.0.0:5700`。
- **观看端（fps-viewer.exe）**：连接 `server_addr`（`IP:端口`），按流内 codec 标记自动选择 H.264/HEVC 解码，并悬浮显示画面。
- **两种路径**：
  1. **局域网直连**（最简）：双方在同一局域网，观看端直接填共享端内网 IP，不需要 frp。
  2. **公网穿透（frp）**：共享端通过樱花 frp 隧道把内网端口映射到公网节点，观看端在任何网络都能连接。

## 2. 产物清单与系统要求

| 文件 | 说明 |
|---|---|
| `fps-host.exe` | 共享端（windowed GUI 控制台；加 `--console` 参数可强制命令行模式） |
| `fps-viewer.exe` | 观看端 |
| `frpc.exe` | 樱花 frp 客户端（**必须自行从樱花控制台下载**，与两个 exe 放同一目录） |
| `config.json` | 配置文件（与 exe 同目录，首次运行自动生成） |
| `logs\` | 日志目录（`app_YYYYMMDD.log`，5MB 滚动 × 5 份） |
| `assets\app.ico` | 图标（安装包自带） |

**系统要求**：Windows 10/11 64 位。共享端需可运行 `fps-host.exe`；观看端无需安装任何环境。

> 也可用 `SakuraVision-Setup-1.0.0.exe` 安装包一键安装（Inno Setup 产物，自动放置两个 exe）。

## 3. 快速部署

### 3.1 路径一：局域网直连（推荐先验证此路径）

1. 共享端双击 `fps-host.exe`，等待控制台出现「服务已启动，监听 0.0.0.0:5700」。
2. 确认共享端内网 IP：`ipconfig` 查看 IPv4 地址（如 `192.168.1.100`）。
3. 观看端双击 `fps-viewer.exe`，在频道管理中将地址改为 `192.168.1.100:5700`。
4. 连接成功即可看到悬浮画面。

> 首帧出现约需 1~2 秒；带宽约几百 KB/s ~ 数 MB/s 取决于分辨率与质量设置。

### 3.2 路径二：公网穿透（frp）

1. 按第 4 节完成樱花 frp 的注册、建隧道、下载 `frpc.exe`。
2. 把 `frpc.exe` 放到与 `fps-host.exe` 相同的目录。
3. 共享端 GUI 的「frpc 区」填写 `token` 与 `tunnel_ids`，点击「启动」（或勾选自动启动后重启）。
4. 在「公网地址」输入框填写观看端要用的地址（如 `节点IP:远端端口`），点「复制」。
5. 观看端把 `server_addr` 设为该公网地址并连接。

## 4. frpc（樱花 frp）配置详解

程序内置 `FrpManager`，启动 frpc 的命令固定为：

```
frpc.exe -f <token>:<tunnel_ids>
```

其中 `token` 为樱花账号的访问令牌，`tunnel_ids` 为隧道 ID（多个用英文逗号分隔，如 `12345,23456`）。

### 4.1 注册与获取 token

1. 打开樱花 frp 官网（https://natfrp.org，备用 https://natfrp.com），注册账号并登录。
2. 进入控制台（https://console.natfrp.com），在「个人中心 / API」页面查看 **访问令牌（token）**。
3. 复制 token 备用（形如一长串十六进制字符）。

### 4.2 创建 TCP 隧道（端口映射在此完成）

1. 控制台 →「隧道列表」→「创建隧道」。
2. 关键设置：
   - **协议类型**：选 **TCP**（本程序为 TCP 实时视频流，不要选 HTTP/HTTPS）。
   - **本地端口**：填共享端监听端口，默认 **5700**。
   - **远端端口**：选择节点提供的一个公网端口（免费节点为随机分配，记下该端口）。
   - **节点**：选离共享端网络较近的节点；免费节点通常为普通 NAT，延迟略高，画面要求高可选优质节点。
3. 创建成功后记下 **隧道 ID**（在隧道列表中每行显示）。

> 映射关系即：`公网节点IP:远端端口 ──► 共享端本地 127.0.0.1:5700`。
> 需要多人同时观看时，一个 TCP 隧道即可承载多个观看端（程序支持多客户端广播）；如需多路不同地址，可创建多条隧道并用逗号填多个 ID。

### 4.3 下载 frpc.exe

控制台「客户端下载」中选择 Windows amd64 版本下载，解压得到 `frpc_windows_amd64.exe`（可改名为 `frpc.exe`），放入共享端 exe 所在目录。程序会自动识别同目录下的 `frpc.exe`、`frpc_windows_amd64.exe` 或 `frpc_windows_386.exe`；如果你安装了 `SakuraFrpLauncher`，也会自动查找 `C:\Program Files\SakuraFrpLauncher\frpc.exe` 等默认安装位置。

> 如果你已经安装了 `SakuraFrpLauncher` / `SakuraFrpService`，程序会自动：
> 1. 在 `C:\Program Files\SakuraFrpLauncher` 等默认目录找到 `frpc.exe`；
> 2. 从 `C:\ProgramData\SakuraFrpService\config.json` 自动读取访问密钥（token）和需要启动的隧道 ID；
> 3. 检测到樱花服务正在运行时，不再重复拉起 frpc，避免端口/隧道冲突。

### 4.4 在程序里配置（二选一）

**方式 A：GUI 操作（推荐）**

共享端控制台 →「frpc 区」：
- `token`：粘贴 4.1 的访问令牌。
- `tunnel_ids`：粘贴 4.2 的隧道 ID（多个用英文逗号分隔）。
- 点「启动」；状态指示变绿表示已连上节点。勾选「自动启动」后程序每次打开会自动拉起 frpc。

**方式 B：直接编辑 config.json**

```json
"frp": {
  "auto_start": true,
  "frpc_path": "frpc.exe",
  "token": "你的访问令牌",
  "tunnel_ids": "12345",
  "public_addr": "节点IP或域名:远端端口"
}
```

- `auto_start`：true 时打开程序自动启动 frpc。
- `frpc_path`：frpc 可执行文件名（默认同目录 `frpc.exe`；也可填绝对路径）。
- `public_addr`：仅用于控制台显示与一键复制，不影响隧道本身。

> 安全提示：token 属敏感凭据，程序写入日志时会自动打码，请勿把 `config.json` 外发。

## 5. 端口映射说明

| 角色 | 端口 | 默认值 | 配置项 | 说明 |
|---|---|---|---|---|
| 共享端监听 | 本地 TCP 5700 | 5700 | `host.port` | 观看端 / frp 隧道连接的本地服务端口 |
| frp 隧道远端 | 节点公网 TCP 端口 | 节点分配 | 樱花控制台创建 | 公网观看端访问的入口端口 |
| 观看端连接 | 目标地址 | `127.0.0.1:5700` | `viewer.server_addr` | 局域网填 `共享端IP:5700`；公网填 `节点IP:远端端口` |

**端口链路（公网场景）**：

```
观看端 ──► 节点IP:远端端口 ──► 樱花节点转发 ──► 共享端 127.0.0.1:5700 ──► fps-host 广播
```

**要点**：
- 局域网场景**不需要** frp，也不需要在路由器上做端口转发（除非要跨网段/跨公网直连）。
- 共享端监听 `0.0.0.0`（`host.listen_host`），保证 frpc 走 `127.0.0.1` 也能连上。
- 改 `host.port` 时，必须同步改樱花隧道的「本地端口」为相同值。

## 6. config.json 配置参考

配置文件与 exe 同目录，缺失时程序自动生成默认配置；旧配置升级时会自动补全新字段（不覆盖已有值）。

### 6.1 共享端 `host`

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen_host` | `0.0.0.0` | 监听地址，保持默认即可 |
| `port` | `5700` | 服务端口，需与 frp 隧道本地端口一致 |
| `fps` | `60` | 目标帧率（采集节流上限），带宽紧张可降为 30 |
| `jpeg_quality` | `80` | JPEG 质量 1~100，越低带宽越小、画面越糊 |
| `scale` | `1.0` | 画面缩放系数（0.5=半分辨率），降低可显著省带宽 |
| `capture.monitor` | `1` | 采集显示器编号（从 1 开始） |
| `capture.region` | `null` | 自定义采集区域 `{"left":0,"top":0,"width":800,"height":600}`；null=全屏（默认全屏，可在共享端 GUI 点击“恢复全屏”一键清空区域） |
| `capture.backend` | `mss` | 采集后端：`mss`（GDI，兼容性最好）/ `dxgi`（DXGI 硬件采集，需装 dxcam，解决独占全屏黑屏） |
| `perf.adaptive` | `true` | 带宽自适应：网络差时自动降质量/缩放 |
| `perf.quality_min` | `40` | 自适应最低质量下限 |
| `perf.scale_min` | `0.6` | 自适应最低缩放下限 |
| `codec.encoder` | `auto` | 视频编码选择：`auto`（自动选最优：HEVC→H.264 硬件优先，软件/JPEG 兜底）/ `hevc`（显式优先 HEVC）/ `nvenc`（H.264 硬件）/ `x264`（H.264 软件）/ `jpeg`（禁用视频编码） |
| `codec.bitrate_kbps` | `6000` | 视频编码码率（Kbps，CBR）。HEVC 在同等画质下带宽约为 H.264 的 50%~70% |
| `codec.keyint` | `30` | 关键帧间隔（帧）。越大带宽越低、首帧/重连恢复越慢 |
| `codec.min_bitrate_kbps` | `1000` | 带宽自适应（ABR）码率下限 |
| `codec.max_bitrate_kbps` | `20000` | 带宽自适应（ABR）码率上限 |
| `codec.preset` | `""` | 编码器预设，空=默认低延迟预设（NVENC p5 / x264 veryfast） |
| `frp.*` | — | 见第 4 节 |

> 共享端 GUI 的「传输参数」区可直接修改 `fps`、`jpeg_quality`、`scale`、`perf.adaptive` 与 `auth.enabled`，
> 点击「应用传输设置」后写入 `config.json` 并即时生效（`fps` 从下一采集帧开始生效）。

### 6.2 观看端 `viewer`

| 字段 | 默认 | 说明 |
|---|---|---|
| `server_addr` | `127.0.0.1:5700` | 默认连接地址（无频道时使用） |
| `display_width` | `480` | 悬浮窗显示宽度（像素），高度按原比例 |
| `alpha` | `0.9` | 窗口不透明度 0~1 |
| `click_through` | `true` | 鼠标穿透（不挡游戏操作） |
| `panel_topmost` | `true` | 悬浮窗置顶 |
| `channels` | `[]` | 频道列表 `[{"name":"默认频道","addr":"IP:端口"}]`；为空时回退 server_addr |

## 7. 常见问题排查

> 排查入口：共享端 `logs\app_当天日期.log`（GUI 内「日志区」实时可见）；frpc 输出也会以 `frpc: ...` 前缀写入日志。

### 7.1 连接与画面

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 观看端一直「连接中/无画面」 | 地址填错 / 端口不通 | 先用局域网直连验证：观看端填 `共享端IP:5700`；`ping 共享端IP` 确认可达 |
| 局域网能连、公网连不上 | frp 未启动或配置错 | 见 7.2；先确认共享端日志出现 `frpc 已启动` |
| 连接秒断 / 一直重连 | 共享端未启动服务或端口占用 | 确认日志有「服务已启动，监听 0.0.0.0:5700」；`netstat -ano \| findstr 5700` 查看监听 |
| 连上但黑屏 | 独占全屏采集黑屏（mss 后端） | 切 `capture.backend` 为 `dxgi`（需装 dxcam），或改为窗口化/无边框全屏 |
| 关闭账户准入后仍提示“需要登录” | 旧版观看端不知道服务端已关闭准入，仍等待登录回复 | 使用本次重新打包的 `fps-host.exe` + `fps-viewer.exe`；观看端会先用空凭据探测，服务端直接放行，不再弹登录框 |
| 公网地址填了 `28689` 连不上 | 观看端地址少了节点域名 | 应填完整地址，例如 `frp-fun.com:28689`（节点域名:远端端口） |
| 画面卡顿、延迟高 | 带宽不足或共享端 CPU 编码压力大 | 降 `fps`/`jpeg_quality`/`scale`，或开启 `perf.adaptive`；游戏场景可只采集指定区域 `capture.region` |
| 有多个观看端时个别人掉线 | 该客户端带宽不足被慢客户端淘汰 | 观看端降低显示宽度；共享端日志会记录「客户端发送失败，已移除（累计发送 x MB）」 |
| 某个观看端网络差导致其他人也卡顿 | 旧版为同步广播，慢客户端会阻塞发送线程 | 新版本每个客户端独立发送线程和最新帧队列，慢客户端只丢自己的帧，不影响其他观看端 |
| 时间戳/播放乱序 | 网络抖动 | 属正常缓冲现象；连续 1~2 秒恢复即正常 |

### 7.2 frp / 公网

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 点「启动」提示缺少 token 或 tunnel_ids | frpc 区未填写 | 在 GUI frpc 区填写后再启动 |
| 提示「未找到 frpc 程序」 | `frpc.exe` 不在 exe 同目录 | 把 `frpc.exe` 放到与 `fps-host.exe` 同一目录（安装包会尝试自动放置） |
| frpc 启动后日志报认证失败/隧道不存在 | token 或隧道 ID 填错 | 核对控制台 token 与隧道 ID；多个隧道用英文逗号分隔，不要有空格 |
| frpc 已启动但公网仍连不上 | 隧道类型/本地端口不对 | 确认隧道是 TCP、本地端口与 `host.port` 一致（默认 5700）；远端端口用节点分配的端口 |
| 免费节点很卡/高延迟 | 免费节点带宽有限 | 换优质节点；降低编码码率（质量/缩放/fps） |
| 公网地址不会填 | 不知道用哪个地址 | 观看端填 `节点IP或域名:远端端口`；在控制台隧道详情可看到公网连接地址，复制到 GUI「公网地址」一键复制 |
| 樱花免费节点被限速/停机 | 免费额度用尽或未实名 | 登录樱花控制台查看流量/状态，按提示实名或充值 |

### 7.3 采集与性能

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 采集到错误的显示器 | 多显示器编号与预期不符 | GUI 采集源区下拉选择显示器，或改 `capture.monitor`（从 1 开始） |
| 想只共享游戏画面 | 全屏占用带宽过大 | 设 `capture.region` 限定区域（如 `{"left":0,"top":0,"width":1280,"height":720}`） |
| `dxgi` 后端采集失败 | 未装 dxcam / 显卡不支持 | 程序会自动回退 mss 并写日志；安装 dxcam：`pip install dxcam --target=.\vendor` 后重新打包 |
| 编码耗时偏高 | 分辨率大 + 质量高 | 降 `scale`/`fps`；性能区实时显示「编码 x.x ms」，>20ms 需要调参 |

### 7.4 启动与打包

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击 fps-host.exe 无反应 | 被安全软件拦截 / 缺运行库 | 查看 `logs\` 是否有当日日志；临时退出杀软后重试；确认是 64 位系统 |
| windowed 模式启动即退 | config.json 损坏 | 删除与 exe 同目录的 `config.json` 重新生成 |
| 需要命令行界面 | 习惯旧版输出 | 运行 `fps-host.exe --console`（可带 `--port 端口` 覆盖端口） |
| 重新打包后 dxgi 失效 | 打包时未带 vendor | 执行 `pip install dxcam --target=.\vendor` 后再跑 `build_exe.bat`（脚本检测到 vendor 目录会自动 `--paths vendor`） |

## 8. 日志与诊断指引

- **共享端日志**：`logs\app_YYYYMMDD.log`（与 exe 同目录），包含性能统计、客户端接入/断开、带宽与淘汰记录、frpc 输出（token 已打码）。
- **共享端 GUI**：控制台内「性能区」（采集/发送 fps、编码耗时、质量、缩放）与「客户端列表」（每客户端实时 KB/s、累计流量）即为在线诊断面板。
- **快速验证链路**：
  1. 局域网内观看端连 `共享端IP:5700` —— 不通则检查防火墙/服务状态。
  2. 公网：先确认共享端日志出现 `frpc 已启动`，再用任意外部网络设备访问 `节点IP:远端端口`。
  3. Windows 防火墙需放行共享端出站/入站 5700 及 frpc 的通信（首次运行弹窗时点「允许」）。
