# 队友视野 TeamVision 安装与部署指南

> 适用于 v1.4.0。本文档覆盖：产物说明、局域网直连部署、公网穿透（外部工具）要点、
> `config.json` 字段参考、快速排障、日志与诊断。常见问题速查见 [`faq.md`](faq.md)。

---

## 1. 系统架构与部署路径

```
┌──────────────┐   TCP 直连（同一局域网）   ┌──────────────┐
│   共享端      │◄───────────────────────────│   观看端      │
│ fps-host.exe │   默认监听 127.0.0.1:5700   │ fps-viewer   │
└──────┬───────┘   （局域网直连需改 0.0.0.0） └──────────────┘
       │ 外部隧道（frp / VPN / 端口映射，任选其一）
       ▼
   公网节点IP:远端端口  ──►  共享端 127.0.0.1:5700
```

- **共享端（fps-host.exe）**：采集屏幕 → H.264/H.265(HEVC) 视频编码（NVENC 硬件优先，软件/JPEG 自动回退）→ TCP 广播给所有已连接观看端。默认监听 `127.0.0.1:5700`（仅本机与隧道可连；同时监听 IPv4/IPv6 回环，兼容 frpc 以 `localhost` 回连），**局域网直连需在「传输参数」里把监听地址改为 `0.0.0.0` 并重启共享端**。
- **观看端（fps-viewer.exe）**：连接 `server_addr`（`IP:端口`），按流内 codec 标记自动选择 H.264/HEVC 解码，并悬浮显示画面。默认开启账户准入，首次连接需注册/登录。
- **两种路径**：
  1. **局域网直连**（最简）：双方在同一局域网，观看端直接填共享端内网 IP。先把监听地址改成 `0.0.0.0`。
  2. **公网穿透**：经隧道工具把内网端口映射到公网（见第 3 节，穿透本身不属于本软件功能范围）。

## 2. 产物清单与系统要求

程序为 **onedir** 形态：每个程序是「exe + `_internal\` 运行库目录」的完整文件夹
（不把自身解压到 `%TEMP%` 运行——那正是杀软/反作弊误报的常见来源）。

| 文件 | 说明 |
|---|---|
| `fps-host\fps-host.exe` | 共享端（windowed GUI 控制台）。发布版以 windowed 打包（console=False），`--console` 仅切换为无 GUI 的后台服务模式、**不会弹出控制台窗口**，此时排障看 `logs\app_*.log`；要真正的命令行输出请从源码运行 `python host.py --console` |
| `fps-host\_internal\` | 共享端运行库（Python 运行时、FFmpeg/NVENC DLL）。**不可删除或拆分到别处** |
| `fps-viewer\fps-viewer.exe` | 观看端（同样带自己的 `_internal\`） |
| `frpc.exe` | 第三方 frp 客户端（**自行从所选隧道服务下载**，放在两个程序目录的上一级；不使用穿透可删除） |
| `config.json` | 配置文件（`%LOCALAPPDATA%\TeamVision\`，首次运行自动生成；源码运行时在项目目录） |
| `accounts.json` | 账户表（同目录，PBKDF2 加盐存储，不含明文密码） |
| `logs\` | 日志目录（`app_YYYYMMDD.log`，5MB 滚动 × 5 份） |
| `assets\app.ico` / `assets\splash.png` | 图标与启动画面（安装包自带；splash 缺失时降级为纯文字） |

**系统要求**：Windows 10/11 64 位。观看端无需安装任何环境。

> 也可用 `TeamVision-Setup-1.4.0.exe` 安装包一键安装（Inno Setup 产物，自动放置两个程序目录）。

## 3. 快速部署

### 3.1 路径一：局域网直连（推荐先验证此路径）

> ⚠️ 共享端默认只监听 `127.0.0.1`。改 `0.0.0.0` 之前，局域网内其他机器连不上。

1. 双击 `fps-host\fps-host.exe`。控制台「传输参数」→ 监听地址改为 `0.0.0.0` →「应用传输设置」→ 重启共享端，等待「服务已启动，监听 0.0.0.0:5700」。
2. 确认共享端内网 IP：`ipconfig` 查看 IPv4 地址（如 `192.168.1.100`）。
3. 双击 `fps-viewer\fps-viewer.exe`，频道管理中地址填 `192.168.1.100:5700`。
4. 首次连接按提示注册/登录（默认开启账户准入），连接成功后即可看到悬浮画面。

> 首帧约需 1~2 秒；带宽几百 KB/s ~ 数 MB/s，取决于分辨率与质量设置。

### 3.2 路径二：公网穿透（外部工具）

**穿透不是本软件的功能**：共享端 GUI 的 frpc 卡片只是拉起外部 `frpc.exe` 的便捷入口
（示例性质，维持现状），token/隧道的注册与创建请在你的隧道服务控制台完成（如樱花 frp：
https://console.natfrp.com ）。隧道只需满足一条：**远端端口 → 共享端 `127.0.0.1:<host.port>`**。
共享端启动后会自动做一次公网回连自检，结果写入日志并在面板提示。

> ⚠️ **明文传输警示**：画面与控制数据走明文 TCP，本软件不做端到端加密。公网暴露等于
> 链路上任何一跳都能看到画面内容——请经由隧道/VPN 接入，保持账户准入开启，
> 并把「账户注册」设为 `仅首个账户` 或 `关闭`；不要直接把 5700 端口映射到公网裸奔。
> 1.4.0 起认证改为挑战-应答（`auth.chal_response=require`），**登录口令不再过网**，
> 但这不改变上述结论：口令安全 ≠ 画面加密，公网接入仍须信任链路或走隧道/VPN。

## 4. 端口速查

| 角色 | 值 | 配置项 | 说明 |
|---|---|---|---|
| 共享端监听 | TCP `5700` | `host.listen_host` + `host.port` | 观看端/隧道连接的本地服务端口 |
| 观看端连接 | `127.0.0.1:5700` | `viewer.server_addr` | 局域网填 `共享端IP:5700`；公网填 `节点地址:远端端口` |

**要点**：
- 改监听地址**必须重启共享端**（监听 socket 只在启动时绑定）；`fps` 等参数即时生效。
- 默认 `127.0.0.1` 为回环双栈（同时绑 `127.0.0.1` 与 `[::1]`），隧道客户端写
  `localhost` 或 `127.0.0.1` 都能连；若日志提示未覆盖 IPv6 回环（如系统禁用 IPv6），
  把隧道本地地址显式写成 `127.0.0.1`。
- 改 `host.port` 时，隧道侧「本地端口」要同步改。

## 5. config.json 配置参考

配置文件在 `%LOCALAPPDATA%\TeamVision\`（源码运行时在项目目录），缺失时程序自动生成默认配置；
旧配置升级时自动补全新字段（不覆盖已有值）。**默认值以代码 `common.py` 的 `DEFAULT_CONFIG`
为单一真源**；若文档与代码不符，以代码为准。

### 5.1 共享端 `host`

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen_host` | `127.0.0.1` | 监听地址。默认只允许本机与隧道接入；局域网直连改 `0.0.0.0`（改完重启） |
| `port` | `5700` | 服务端口，需与隧道本地端口一致 |
| `fps` | `30` | 目标帧率（采集节流上限）；带宽紧张可下调 |
| `jpeg_quality` | `80` | JPEG 质量 1~100，越低带宽越小、画面越糊 |
| `scale` | `1.0` | 画面缩放系数（0.5=半分辨率），降低可显著省带宽 |
| `capture.monitor` | `1` | 采集显示器编号（从 1 开始） |
| `capture.region` | `null` | 自定义采集区域 `{"left":0,"top":0,"width":800,"height":600}`；null=全屏（GUI 可一键「恢复全屏」） |
| `capture.backend` | `dxgi` | 采集后端：`dxgi`（DXGI 硬件采集，低延迟、解决独占全屏黑屏；需装 dxcam，不可用自动回退 `mss`）/ `mss`（GDI，兼容性最好） |
| `net.max_clients` | `32` | 同时在册连接上限（含握手中），超限连接在建连即被拒 |
| `perf.adaptive` | `true` | 带宽自适应：网络差时自动降质量/缩放 |
| `perf.quality_min` | `40` | 自适应最低质量下限 |
| `perf.scale_min` | `0.25` | 自适应最低缩放下限 |
| `codec.encoder` | `auto` | 编码选择：`auto`（HEVC→H.264 硬件优先，软件/JPEG 兜底）/ `hevc` / `nvenc` / `x264` / `jpeg`（禁用视频编码） |
| `codec.bitrate_kbps` | `2500` | 视频码率（Kbps，vbr）。HEVC 同画质带宽约为 H.264 的 50%~70% |
| `codec.keyint` | `60` | 关键帧间隔（帧）。越大带宽越低、首帧/重连恢复越慢 |
| `codec.min_bitrate_kbps` / `max_bitrate_kbps` | `400` / `6000` | 带宽自适应（ABR）码率上下限 |
| `codec.preset` | `""` | 编码器预设，空=默认低延迟预设（NVENC p5 / x264 veryfast） |
| `auth.enabled` | `true` | 账户准入：观看端必须注册/登录后才能取流 |
| `auth.allow_register` | `open` | 自助注册策略：`open` / `bootstrap`（仅首个账户可注册）/ `closed`。公网暴露时建议 `bootstrap` 或 `closed` |
| `auth.auth_timeout` | `240` | 认证阶段总时限（秒），代码有 240 秒下界，改小会被自动抬高 |
| `auth.chal_response` | `require` | 认证方式：`require`=挑战-应答（口令不过网，1.4.0 起默认）/ `allow_legacy`=临时允许旧版观看端直发口令（每条都记 WARNING）。仅建议作为升级过渡，一个版本周期后移除 |
| `frp.*` | — | 外部 frpc 拉起参数（`auto_start`/`frpc_path`/`token`/`tunnel_ids`/`public_addr`），示例性质、维持现状；token 写日志时自动打码，勿外发 `config.json` |
| `update_check.enabled` | `true` | 更新提示（共享端与观看端共用）：启动后查一次 GitHub Releases 最新 tag，比当前版本新时在状态栏提示，结果缓存 24h、失败静默；**不做自动更新**，不想外连可置 `false` |
| `config_version` | `2` | 配置结构版本（程序维护，请勿手改） |

> GUI「传输参数」区可直接改 `listen_host`、`auth.enabled`、`auth.allow_register`、`fps`、
> `jpeg_quality`、`scale` 与 `perf.adaptive`，点「应用传输设置」写入 `config.json`。
> 「账户管理」按钮（1.4.0 起）可列出/添加/删除账户与重置口令——纯本地写 `accounts.json`，
> 与自助注册策略无关，`closed` 下也能给队友开号；删除最后一个账户会要求二次确认（防自锁）。

### 5.2 从 1.3.0 及更早版本升级

旧配置里如果显式写着 `listen_host: 0.0.0.0` 且 `auth.enabled: false`，首次启动会**自动**升级为
`127.0.0.1` + 准入开启，并在日志里逐条列出改动。迁移只做一次（写回 `config_version: 2`），
只动这两个安全相关字段；`fps`、`capture.*`、`codec.*`、频道列表等原样保留；
自定义监听地址（如 `192.168.1.5`）不会被改写。想恢复旧行为：「传输参数」里改回并重新应用。

**1.4.0 新增（D1 挑战-应答）**：共享端升级后默认 `require`，**1.3.x 及更早的观看端会被拒
（提示「观看端版本过旧，请更新后重试」）**。请让观看端一并升级到 1.4.0；暂时做不到时，可在
`config.json` 的 `host.auth` 加 `"chal_response": "allow_legacy"` 并重启共享端过渡
（旧版直发口令会记 WARNING，升级完成后请改回 `require`）。已有账户无需重建。

### 5.3 观看端 `viewer`

| 字段 | 默认 | 说明 |
|---|---|---|
| `server_addr` | `127.0.0.1:5700` | 默认连接地址（无频道时使用） |
| `display_width` | `480` | 悬浮窗显示宽度（像素），高度按原比例 |
| `alpha` | `0.9` | 窗口不透明度 0~1 |
| `click_through` | `true` | 鼠标穿透（不挡游戏操作） |
| `panel_topmost` | `true` | 悬浮窗置顶 |
| `channels` | `[]` | 频道列表 `[{"name":"默认频道","addr":"IP:端口"}]`；为空时回退 server_addr |

## 6. 快速排障

> 用户向「现象 → 处理」速查表已下沉到 [`faq.md`](faq.md)；本节保留需要看日志/改配置的深度排障。
> 排查入口：共享端 `%LOCALAPPDATA%\TeamVision\logs\app_当天日期.log`（GUI「日志区」实时可见）。

### 6.1 连接与画面

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 连接秒断 / 一直重连 | 共享端未启动服务或端口占用 | 确认日志有「服务已启动，监听 …」；`netstat -ano \| findstr 5700` 查看监听 |
| 公网连不上（隧道已建） | 隧道本地端口与 `host.port` 不一致，或隧道未到本机 | 共享端日志若有「公网隧道自检失败：TCP 已连通…但未收到握手」，说明隧道打到了本机但没指向服务端口；完全无接入记录则查隧道服务侧 |
| 有多个观看端时个别人掉线 | 该客户端带宽不足被慢客户端淘汰 | 观看端降低显示宽度；共享端日志记录「客户端发送失败，已移除（累计发送 x MB）」 |
| 时间戳/播放乱序 | 网络抖动 | 属正常缓冲现象；连续 1~2 秒恢复即正常 |

### 6.2 采集与性能

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 采集到错误的显示器 | 多显示器编号与预期不符 | GUI 采集源区下拉选择显示器，或改 `capture.monitor`（从 1 开始） |
| 想只共享游戏画面 | 全屏占用带宽过大 | 设 `capture.region` 限定区域（如 `{"left":0,"top":0,"width":1280,"height":720}`） |
| `dxgi` 后端采集失败 | 未装 dxcam / 显卡不支持 | 程序会自动回退 mss 并写日志；安装 dxcam 到 vendor：`pip install --no-deps "git+https://github.com/ra1nty/DXcam" comtypes --target=.\vendor` 后重新打包。**关键提醒**：PyPI 上的 `dxcam` 只有滞后的 0.0.5，与项目实测/已 vendor 的 0.3.0 不是同一个东西，**不要**用 `pip install dxcam`（会装错版本）；dxcam 必须取自 GitHub `ra1nty/DXcam`，该仓库无 release tag，装的是默认分支 HEAD，装完核对 `vendor\dxcam-*.dist-info` 是否为 0.3.0（要精确复现就 pin 到具体 commit）。`--no-deps` 避免把 numpy 塞进 vendor（numpy 由 conda 提供，否则与观看端分叉）；comtypes 必须显式带上：conda 环境没有它，而 dxcam 依赖它 |
| 编码耗时偏高 | 分辨率大 + 质量高 | 降 `scale`/`fps`；性能区实时显示「编码 x.x ms」，>20ms 需要调参 |

### 6.3 启动与打包

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击 fps-host.exe 无反应 | 被安全软件拦截 / 缺运行库 / `_internal` 目录缺失 | 查看 `%LOCALAPPDATA%\TeamVision\logs\` 当日日志；确认 `fps-host\` 里的 `_internal\` 与 exe 在一起（onedir 形态不可只拷贝 exe）；确认是 64 位系统 |
| windowed 模式启动即退 | config.json 损坏 | 删除 `%LOCALAPPDATA%\TeamVision\config.json` 重新生成（旧文件会以 `.corrupt-<时间戳>` 留存） |
| 升级后局域网连不上了 | 配置已按安全默认迁移为只监听 `127.0.0.1` | 见 §5.2：控制台把监听地址改回 `0.0.0.0` 并重启；日志里有迁移说明 |
| 需要命令行界面 | 习惯旧版输出 | 发布版 `fps-host.exe` 为 windowed 打包，`--console` 只切到无 GUI 后台模式、**不弹控制台窗口也无 stdout 日志**；要真正的命令行输出请从源码运行 `python host.py --console`。`--port 端口` 覆盖端口对源码版与发布版都有效；发布版排障看 `logs\app_*.log` |
| 重新打包后 dxgi 失效 | 打包时未带 vendor | 按 §6.2 的 vendor 命令装入后再跑 `build_exe.bat`（fps-host.spec 的 `pathex=['vendor']` 会无条件带上 vendor 中的 dxcam/comtypes） |

## 7. 日志与诊断指引

- **共享端日志**：`%LOCALAPPDATA%\TeamVision\logs\app_YYYYMMDD.log`（源码运行时在项目目录），包含性能统计、客户端接入/断开、带宽与淘汰记录、frpc 输出（token 已打码），以及启动时的暴露面提示（监听全网卡 / 准入关闭 / 自助注册开放都会写 WARNING）。
- **共享端 GUI**：控制台「性能区」（采集/发送 fps、编码耗时、质量、缩放）与「客户端列表」（每客户端实时 KB/s、累计流量）即为在线诊断面板；「一键诊断」导出诊断包（自动打码 token/密码）。
- **观看端诊断**：面板导出的诊断包含各频道**延迟 P50/P95**（30 秒窗口，E4 埋点）；跨机墙钟不完全同步，延迟读数**以相对趋势为主**，绝对值参考 RTT/2。
- **快速验证链路**：
  1. 局域网内观看端连 `共享端IP:5700` —— 不通则检查防火墙/服务状态。
  2. 公网：先确认共享端日志出现隧道接入与自检结果，再从外部网络设备访问 `节点地址:远端端口`。
  3. Windows 防火墙需放行共享端 5700 的入站/出站及隧道客户端通信（首次运行弹窗时点「允许」）。
