**B1 实测校准（对 §0 表第 3 行与 §2.4 的更正）**

1. `opencv-python-headless` 在 **Windows 上与常规包二进制等价**：两包内 `cv2.pyd`（85,848,064 B）与 `opencv_videoio_ffmpeg500_64.dll`（30,876,160 B）逐字节一致 → **体积收益为 0**。换 headless 的价值在 Linux/CI（不拖 Qt/GTK 依赖链），该切换已保留。
2. 实际收益来自 **spec 层二进制剔除**（两个 spec 对 `a.binaries` 过滤）：`cv2\opencv_videoio_ffmpeg*.dll` **30.9MB**（全仓零 `VideoCapture/VideoWriter` 调用）+ `PIL\_avif*.pyd` 7.9MB + `PIL\_webp*.pyd` 0.4MB → 单端 **246MB → 208MB**（cv2 目录 112→82MB、PIL 11→2.9MB）。
3. `av.libs`（63MB）**评估结论：不可剪**。25 个 DLL 逐个移除测试均使 `import av` 报 `DLL load failed while importing _core`（含 SvtAv1Enc/dav1d/libvpx/opus/mp3lame/webp/avfilter/avdevice/libvpl），全部是导入表硬依赖。
4. `excludes` 已补齐（unittest/doctest/pydoc/IPython/jupyter/pytest/matplotlib/scipy/pandas/PyQt/wx 等）：当前干净环境中贡献 ≈0，作防御性收敛保留（防未来误引入）；`tkinter` 明确**不在**排除列表（`host_ui.py` 全靠它）。
5. 安装包实测：用 ISCC `/O` 输出到临时目录完成编译（**未触碰 `dist/TeamVision-Setup-1.3.0.exe`**）：**140,729,832 B → 116,359,583 B（134.2 → 111.0 MiB，−17.3%）**。
6. 验证：全量回归 **485 项 OK / 115.9s**；冻结包冒烟 `SMOKE_VIDEO_OK`（hevc_nvenc，309 视频帧）+ `SMOKE_JPEG_OK`（324 JPEG 帧），运行期无 Traceback/ERROR。

> 目标校准：单端 ≤150MB 需**替换 cv2** 才可能达到——`cv2.pyd` 86MB 是 Windows 单体二进制不可拆，`av.libs`/`numpy.libs` 实测/评估均不可剪；
> 可达基线更新为 **208MB / 111MB**。若未来把 5 个 cv2 API 换成 PIL+numpy 实现可再省 ≈81MB/端，但 viewer 的 JPEG 解码路径对帧率敏感，需单独实测评估（不在本轮范围）。

### 2.2 【性能】观看端上屏链"先全尺寸转换、后缩放"（实测可降 96%）

> ✅ **A1 已实施（2026-09-17）**：两处均改"先 `cv2.resize(INTER_AREA)` 后 `cvtColor`"，实测 9.12ms → 3.45ms（见 0.1）。本节保留原始分析。

- **位置**：主画面 `viewer.py:2981-2988`；控制面板预览 `viewer.py:2094-2103`（两处同构；A1 后为 `2069-2073`/`2955-2960`）。
- **现状链**：`cv2.cvtColor(整帧 1080p)` → `Image.fromarray(整帧)` → `PIL resize(→361px)` → `PhotoImage`。
  即：对 1920×1080 做全量色彩转换后，再把结果丢给 PIL 缩小——99.9% 的转换输出像素从未被使用。
- **实测（本机，1080p → 361px 宽，40 次均值，见附录 A 复现脚本）**：

| 实现 | 耗时/帧 | 相对 |
|---|---|---|
| 现状：全帧 cvtColor → PIL.BILINEAR resize | **9.12 ms** | 基准 |
| 改法 1：`cv2.resize(INTER_AREA)` → 小图 cvtColor | 3.45 ms | **−62%** |
| 改法 2：`cv2.resize(INTER_LINEAR)` → 小图 cvtColor | 0.16 ms | **−98%** |

- **影响**：`_show_frame` 在主线程（Tk 事件循环，15ms 周期 poll）执行；1080p@30 时每秒占用主线程约 **0.27s**，
  是"画面偶发卡顿/面板刷新不跟手"的确定性来源之一。改动本身约 6 行。
- **建议**：先 `cv2.resize`（下采样建议 `INTER_AREA`，画质最好、3.45ms 仍远低于现状；对帧率极敏感的悬浮窗可评估 `INTER_LINEAR`），
  再对小图做 `cvtColor`/`fromarray`。注意同步补桩：`tests/test_item98_draw_cache.py:92-99` 现只显式桩了 `cvtColor`（需补 `resize`，
  返回带 `shape` 的对象）。

其他性能项（按性价比排序，均较小）：

| 项 | 位置 | 量化 | 建议 |
|---|---|---|---|
| 中继路径整帧拷贝 2–3 次（校验切片被丢弃 + 重新打包） | `common.py:289`、`host.py:1241`、`host.py:1859` | 6Mbps 下约 2.2MB/s，CPU <0.1% | 低优先；转发可用原始切片省 2 次拷贝 |

### 2.4 【分发】体积大头仍是 cv2 与 av；spec 无任何排除

- `dist/fps-host/_internal` 实测：**cv2 目录 112MB**（`cv2.pyd` 86MB + `opencv_videoio_ffmpeg500_64.dll` 31MB，
  后者是 opencv 自带的 ffmpeg 后端，本项目并不使用）、av.libs 63MB、numpy.libs 20MB、PIL 11MB、libcrypto 5.1MB。
  （B1 后实测：cv2 82MB、PIL 2.9MB，单端 208MB——见 0.1）
- 全仓 cv2 调用面只有 5 个 API（`resize`/`cvtColor`/`imencode`/`imdecode`/`absdiff`），
  **0 处 GUI/VideoIO**（imshow/namedWindow/waitKey/VideoCapture/VideoWriter 合计 0 命中）→ 已换 `opencv-python-headless`。
  **2026-09-17 实测更正**：Windows 上 headless 与常规包**二进制等价**（体积中性），收益在 Linux/CI；换 headless 本身不省体积。
- **2026-09-17 实测更正**：`av.libs` 63MB **不可剪**——25 个 DLL（SvtAv1Enc/dav1d/libvpx/opus/mp3lame/webp/avfilter/avdevice/libvpl 等）
  逐个移除测试均导致 `import av` → `DLL load failed while importing _core`，全部是导入表硬依赖。
  真实可剪项是 `cv2\opencv_videoio_ffmpeg*.dll`（30.9MB，零 VideoIO 调用）与 `PIL\_avif*.pyd`/`PIL\_webp*.pyd`（8.3MB），
  已通过两个 spec 的 `a.binaries` 过滤落实；`excludes` 亦从 `[]` 补齐（防御性，见 0.1）。
- 无自动更新/更新提示机制；README 无安装包预期提示（SmartScreen"未知发布者"、签名现状）。
